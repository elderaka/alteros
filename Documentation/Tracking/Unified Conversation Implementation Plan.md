# Unified Conversation Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement M1: a deterministic, headless-testable authored-first conversation planner with candidate retrieval, channel-aware selection and completion counters; do not claim a working Live chat.

**Architecture:** Reuse the existing Topic condition evaluator, selector and history. A provider-neutral planner accepts synthetic or later model judgments and returns a validated authored selection, generated occurrence, clarification or unavailable outcome. It performs no network, UI, TTS or game effects.

**Tech Stack:** Plain C# compatible with Unity 6000.4.4f1; existing NUnit/source-check tooling. Python/LangGraph/Pydantic/OpenRouter integration is M2, not an M1 dependency.

**Spec:** [[Unified Conversation Design]]. Approved product direction; execution defaults and M1 scope are planner recommendations for review.

## Task 1: define the provider-neutral input/output contract and channels

**Files:** Create the contracts/validator and `ConversationContractTests.cs` in the above folders; modify `Assets/AlterOS/Topics/TopicDefinition.cs` and `TopicDefinitionValidator.cs` only for optional channel metadata. Add synthetic accepted/rejected JSON fixtures under `Tools/Conversation/Fixtures/`.

**Interfaces:** Namespace `AlterOS.Conversation`, public plain DTOs with lower-camel wire fields.

- `ConversationRequest`: schemaVersion=1, requestId, sessionId, channel (`direct|phone`), text, activeResponseId and activeTopicId (optional host-owned continuation context). activeTopicId requires activeResponseId; a response without a canonical Topic may have no activeTopicId.
- `TopicCandidateCard`: topicId, prompt, examples (up to three actual anchors), similarity and authoredAvailability (`unchecked|ready|blocked`). Retrieve emits unchecked; PrepareForJudgment annotates ready/blocked before judgment. Reject unchecked cards when validating a supplied judgment. Cards are host-produced, never model-authoritative.
- `TopicCandidateSet`: ordered cards, indexIdentity, source (`local_gte|synthetic`); zero cards is valid. No provider secrets or full graphs.
- `ConversationJudgment`: schemaVersion=1, requestId, kind (`existing|existing_uncovered|continue|clarify|novel_candidate`), topicId, referencedTopicIds, reply, suggestedReplies. `existing` and `existing_uncovered` require a supplied ID and no reply; `continue` requires activeResponseId and reply; `clarify` needs reply and no topicId; `novel_candidate` needs reply and no invented canonical ID. Every declared topicId/reference must be in supplied cards or match the host activeTopicId, and must resolve in the catalogue. For existing/existing_uncovered, referencedTopicIds includes topicId; continue includes activeTopicId when present. Novelty may reference known subjects as context, but grants no new canonical ID.
- `ConversationReply`: nodes (`List<CanonicalDialogueNode>`). M1 generation uses a linear ordered list of Alterra-only nodes, unique IDs, empty graph choices; nextId is empty (implicit next) or the next listed ID. Last nextId is empty. No fake player lines, arbitrary voice/audio keys, animations, graph loops or action/effect fields.
- `SuggestedPlayerReply`: label, prompt. No path/action/tool fields. Suggestions belong to the response, not graph choices.
- `ConversationPlan`: requestId, outcome (`authored|generated|clarify|unavailable`), topicId, scenarioId, reply, suggestedReplies, diagnosticCode and isNovelCandidate. An unavailable plan has no playable payload. Planning does not mutate history.
- `ConversationContractValidator.ValidateRequest(ConversationRequest)` and `ValidateJudgment(ConversationRequest, TopicCandidateSet, ConversationJudgment, ISet<string> allowedExpressions)` return a list of errors; invalid input never starts playback.
- `ConversationContractValidator.ParseRequest(string json): ConversationRequest` and `ParseJudgment(string json): ConversationJudgment` reject malformed JSON, duplicate properties, missing required properties, unknown properties and wrong scalar types with FormatException before semantic validation. Use the existing .NET JSON reader (`JsonReaderWriterFactory.CreateJsonReader`) to inspect the allowed shape and materialize the DTOs; no regex-based JSON parsing or new package. The protocol read limit is 128KiB UTF-8 for either object, separate from the text bounds. Reject explicit null for required arrays/objects; optional context strings may be empty, never arbitrary extra fields.
- Add `List<string> channels` to TopicScenario; absent/empty means either, otherwise a nonduplicate subset of direct/phone. Unknown values invalidate the definition. No authored corpus rewrite.

## Task 3: retrieve candidate cards and select authored scenarios by channel/experience

**Files:** Create `TopicCandidateRetriever.cs` and `ConversationSelectionTests.cs` (covering retrieval and selection); modify `TopicScenarioSelector.cs` with a conversation-specific entry point, sharing its existing evaluation code.

**Interfaces:**

- `TopicCandidateRetriever.Retrieve(float[] query, string queryIndexIdentity, IEnumerable<TopicFamilyAnchorVector> anchors, string anchorIndexIdentity, IReadOnlyDictionary<string, TopicDefinition> catalogue, string source): TopicCandidateSet`. Require equal, nonempty query/anchor identities, then top eight by existing matcher score, tie by ordinal topicId. Copy at most three actual anchor examples; no invented descriptions or private history. Source is `local_gte|synthetic`; set indexIdentity to the shared identity.
- `TopicCandidateRetriever.PrepareForJudgment(TopicCandidateSet retrieved, IReadOnlyDictionary<string, TopicDefinition> catalogue, IReadOnlyDictionary<string, TopicInstance> authoredInstances, TopicContext context, TopicHistory history, DateTimeOffset nowUtc, string channel): TopicCandidateSet`. Return copied cards annotated ready/blocked by the shared conversation selector using draw=0 for availability only. This pure pre-judgment step must run before a model/fake judge sees cards. Plan rechecks afterwards; the cached availability flag cannot authorize playback.
- `TopicScenarioSelector.SelectForConversation(TopicDefinition definition, TopicInstance instance, TopicContext context, TopicHistory history, DateTimeOffset nowUtc, double draw, string channel): TopicSelectionResult`. Keep Select's legacy weighted behavior. Reuse one gate/weight evaluator; channel is an additional eligibility condition. For conversation selection: eligible positive weights -> highest priority -> unseen scenarios if any -> existing weighted draw. A completed higher-priority repeatable scenario still outranks a lower-priority unseen scenario.

## M1 acceptance and stopping conditions

Pass: real shared C# rules implement authored-first planning, unchanged priority
and once-instance semantics, safe v1 migration, accurate counters, channel gates,
synthetic RAG judgments and no publication/effect bypass. Headless checks run
without a key or Unity process. Existing source regressions pass or a narrowly
identified pre-existing tool blocker is reported. Compile and runtime evidence
remain separate. Re-review after unexpected shared API edits from another session.

Stop/escalate: production catalogue/layout migration required; a conflicting
edit cannot be preserved; a new dependency or destructive save migration is
necessary; testing requires closing the unsaved Editor; a source contract is
incompatible with the agreed design. Do not expand into M2 to make M1 look live.
