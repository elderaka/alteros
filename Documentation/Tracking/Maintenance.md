## In-game generated content is excluded

The shared catalogue enumerates authored content, not each player's AI-generated
dialogue, personal catalogue/overlay, memories, or conversations. Document the
shared generated format and its supported versus planned fields, validation,
indexing, speech/publication gates, storage ownership, and invalidation policy
instead. Use synthetic examples, not copied player records. Existing archive
metadata is scaffolding, not proof that the target publication pipeline works.

Project agents follow the repository-root `AGENTS.md` for orientation and
documentation upkeep; this vault does not require an additional memory skill.

## Status vocabulary

Use separate axes: design (proposed / approved / superseded), implementation (absent / scaffold / implemented), wiring (absent / partial / wired / not-applicable), verification (not-run / passed / failed / blocked, with date and evidence scope).

Content readiness is separate again: a draft/JSON/SQL row existing does not mean
validated, selected for build, published, installed, eligible, indexed, voiced or
runtime verified. A schema field's presence is not proof of consumer enforcement.

## Route snapshot refresh

The initial route notes are a point-in-time mechanical extraction, not a live Obsidian database. No automatic refresh worker/plugin was installed.

For the dated legacy-JSON snapshot, after edits to its retained source:

1. Enumerate every JSON beneath the Generic directory; parse and group by `routing.routeId`.
2. Refresh source path, definition ID, schema/source, SHA-256, time fields, required/blocked context, priority, all routing examples, and node/choice/audio-key counts.
3. Add/remove route notes and update the index; flag malformed content, missing paths, or duplicate IDs instead of silently skipping.
4. Keep human interpretations out of extracted values. Canonical mappings require review against individual semantic notes; absence is “unmapped,” not “none intended.”
5. Update the snapshot date and record changed routes. Do not hand-edit the snapshot to fix runtime content.
6. Revalidate links, source hashes, JSON parsing, and counts. Runtime/audio checks remain separate.

Compare snapshot hashes only against their declared legacy source; do not claim
these dated route notes represent the SQL release. Current SQL catalogue
documentation must use the validated shared-content export/snapshot with
release/source revision hashes. The authoring exporter exists and currently writes
revision-63 JSON review output under `Content/AuthoringExports/`; it does not refresh
these notes automatically. If a validated snapshot is unavailable, report the gap
rather than scanning old files as live authority. No automatic refresh service is
implied.
Never enumerate private user content, memories or transcripts into shared notes.

## Review fields for new dialogue

Track content ID, source directory, canonical Intent/Topic/Tone references, topic anchors, local anchors, eligibility gates, priority, cooldown/repetition, trigger examples, negative/ambiguous examples, node transitions, game effects, tool requests, speech policy/cache revision, dependencies, review status, and acceptance evidence. Mark unsupported fields as design-only; do not insert them into current schema without an implementation task.
