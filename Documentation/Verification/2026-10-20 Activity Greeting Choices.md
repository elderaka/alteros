# Activity choices in the E greeting

The human requested Come here, Follow me and Drink water in the existing
E-interaction choice list shown in their screenshot. Added three **local action
shortcuts**, not generated suggestions, a new Topic catalogue or a new UI.

## Implementation

- `Assets/StreamingAssets/Dialogue/topic/activity_options.json` owns the English
  labels, allowlisted capability IDs and targets. Shared format is an `options`
  array of `{label, capabilityId, target}`. No personal content or provider data.
- `Assets/AlterOS/Activities/ActivityGreetingMenu.cs` filters those entries against
  current host capabilities/target bindings; rejects unknown actions, duplicates
  and entries while an activity, provider turn or Scenario owns the interaction.
- `DirectConversationBridge.AppendScenarioTopicOffers` adds eligible entries to
  the existing greeting choices. Selection rechecks availability, gives the
  request fresh host run/step identity and calls the existing activity port.
  Accepted requests close the exchange; rejection never bypasses the host.
- `DialogueManager` dispatches the `activity_start` choice to that method.
  Existing authored Canvas/world-choice template still owns appearance/layout.
  No scene/prefab/reference changes. Existing Stop following choice remains.
- These shortcuts start standalone reusable activities, not the test Scenario
  fixture question/closing sequences. They make no LLM/TTS call. They do not
  interrupt/replace a running or suspended Scenario behind the player's back.
